# 브리프 받아 작업하기

브리프는 "어떤 검색어를 노리고 무엇을 담을지" 의 결정이다.
글쓰기·코드 자체는 CLAUDE.md 의 규칙(A절 가이드, B절 도구 수정, new-tool 스킬)을 따른다.

1. `_briefs\<파일>.md` 를 끝까지 읽는다. 특히 노리는 검색어 표, 꼭 다룰 항목, 연결할 도구, 이미지 지시.

2. **검색어 반영**
   - 주 검색어: 제목(h1), 머리말 `title`·`description`·`keywords` 에 자연스럽게 넣는다.
   - 보조 검색어: 본문 소제목(`##`)에 자연스럽게 넣는다.
   - 억지 반복 금지. 문장이 어색해지면 넣지 않는다. 읽는 사람에게 도움이 되는 것이 먼저다.

3. "꼭 다룰 항목" 은 하나도 빠뜨리지 않는다.
   사실 확인이 안 되는 항목은 CLAUDE.md A절 3번대로 쓰지 말고 `.done.md` 에 적는다.

4. 연결할 도구는 브리프에 적힌 파일명으로 `[[tool:파일|설명]]` 카드를 만든다(머리말 `tools` 에도 추가).
   `nav.js` GROUPS 에 없는 파일이면 쓰지 않고 `.done.md` 에 적는다.

5. **이미지**: `_briefs\assets\<slug>\` 에 이미지가 있으면 브리프의 위치·alt·loading 지시대로 쓰고, 없으면 넣지 않는다.
   `_briefs\assets\` 는 원본 보관용(커밋 제외)이라 사이트에 쓰는 파일은 공개 경로(예: `guide/img/<slug>/`)로 복사해 커밋한다.
   `build-guides.py` 가 이미지 문법을 지원하지 않으면 임의로 고치지 말고 먼저 보고하고 묻는다.

6. 저장·보고·올리기는 CLAUDE.md A절(가이드)·B절(도구 수정)과 같다.

7. 브리프 내용이 현재 사이트 상태와 다르면(예: "미공개" 라고 적힌 글이 이미 발행됨)
   브리프를 따르되 어긋난 점을 `.done.md` 에 적어 Growth 가 알 수 있게 한다.

8. 작업 후 `_briefs\<파일>.done.md` 를 쓴다.
   (예: `2026-09-25-annual-leave.md` → `2026-09-25-annual-leave.done.md`)

   ```
   # 브리프 반영 기록: <브리프 제목>
   - 브리프: _briefs\<파일>.md
   - 날짜: YYYY-MM-DD
   - 실제 제목:
   - 저장 경로: guide/src/<slug>.md (배포 주소: /guide/<slug>.html)
   - 커밋: 해시 7자리 또는 "미커밋"
   ## 반영한 검색어
   - 주: <검색어> — 제목·title·description·keywords 중 어디에
   - 보조: <검색어> — 어느 소제목에
   ## 빠뜨린 항목
   - 꼭 다룰 항목 중 빠진 것과 이유 (없으면 "없음")
   ```

   선택 항목을 하지 않았으면 이유도 함께 적는다.

9. 브리프 파일(`.md`)은 고치지 않는다. `_briefs\` 의 파일은 커밋하지 않는다.
